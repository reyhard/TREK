## Release and retained behavior

- Previous fork head: `ba6709207c7db4ee99cdd9f78f94fd28940a5dc9` (4.1.1).
- Upstream release: `v4.2.0`, commit `09ce5cb73`.
- Integrated with a normal merge, retaining the fork's history and customizations.
- Preserved track-aware routing and movement totals, POI repositioning, recommended
  place duration, timeline planning, selected-day transit visibility, cost/reservation
  linking, transit endpoint editing, and the removal of the static-token notice.
- Combined upstream transit “Edit details” with the fork's endpoint editor, retaining

  desktop sidebar so track-aware routing and the displayed hotel legs agree.
- Retained both the fork's settings migration tests and upstream offline-language tests.
- Updated Helm/chart assertions and the Sonar workflow version to 4.2.0.

## Database rehearsal

A SQLite online backup of the live 4.1.1 database was migrated in isolation from
schema 200 to 205. Users, trips, places, reservations, and journeys retained their
row counts. `integrity_check` returned `ok`; `foreign_key_check` returned no rows.
Running the migrations a second time also succeeded.

The pre-upgrade backup is stored outside Git at
`/opt/trek/backups/4.2.0-upgrade/travel-4.1.1.db` with restrictive permissions.
Production data was not migrated by this rehearsal.

## Rollout

The local deployment uses `/opt/trek/compose.dev.yml` and may use the
`compose.dev-fast.yml` bind-mount overlay. Package manifests and the lockfile changed,
so rebuild the runtime image when deploying rather than only restarting it.

Before deployment, take a fresh SQLite backup and retain the current image and
built output. Build from the updated `/opt/trek/TREK` checkout and recreate the app
using the compose files active on the running container. Check `/api/health`, the
reported application version, login, the planner, MCP, and installed plugins.

Rollback requires the previous image/output and the pre-upgrade database backup;
stop the app before restoring the database and its matching SQLite sidecars.
